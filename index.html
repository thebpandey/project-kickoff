Four states keep the work legible.

The interview adapts to the project, but the lifecycle stays stable. Every state records what is known, what is approved, and what still needs an answer.

STATE 01

Discovery

Inspect the idea or audit the existing project. Ask one unresolved question and save the answer.

STATE 02

Approved planning

Turn evidence into explicit product, scope, experience, technical, and execution decisions.

STATE 03

Setup

Prepare only approved scope: dependencies, one tracker, instructions, and a minimal scaffold.

STATE 04

Ready for handoff

Validate the plan, tracker mapping, scaffold, and bounded handoff before implementation starts.

Boundary

Project Kickoff plans and prepares. It does not implement product features or start Agent-Team as a side effect.

One answer. One recorded decision.

Five approval stages keep the interview small enough to finish and the result detailed enough to resume. They are a sequence of decisions, not five rigid scripts.

What gets recorded

  • Stable DEC-### decisions with source and rationale.
  • Stage approvals APR-001 through APR-005.
  • One pending question and the next action.
  • Approved PRD.md, DESIGN.md, and PLAN.md.

What remains yours

  • Choose the stack, tracker, scope, and design direction.
  • Approve each stage before dependent setup.
  • Keep one live tracker and one canonical integration branch.
  • Resume later without reconstructing the interview.

A clean boundary between planning and building.

When implementation remains, Project Kickoff writes and validates .project-kickoff/AGENT_TEAM_HANDOFF.json. The handoff contains approved task IDs and facts; Agent-Team owns runtime teams, capability preparation, review, and integration.
